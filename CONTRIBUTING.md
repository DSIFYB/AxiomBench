# Добавление заданий

1. Указать навык, условие, ограничения, источник и лицензию. Для стороннего набора сначала заполнить manifest из docs/SOURCES.md.
2. Сохранить новый стабильный ID и новую версию набора. Не менять старые опубликованные ответы незаметно.
3. Независимо проверить решение. Для C++ приложить доверенный эталон, границы, отрицательные случаи и тест, который отличает исходный баг от правильного кода.
4. Для общей логики исключить неоднозначные предпосылки. Для математики не заменять проверку вывода совпадением итогового числа, если задача просит доказательство.
5. Проверить дубликаты и слишком похожие варианты, отметить публичность и риск попадания в обучение.
6. Запустить validate и релевантные тесты. Не запускать неизвестные/model-generated программы через tools/verify_references.py.

Public dev используется для отладки. Материалы private eval в публичный PR не включать. После вычитки и калибровки записать решение review и только тогда использовать набор для сравнительного отчёта.

Для изменения evaluator добавлять тесты на реальные ошибки оценки: типы JSON, пропущенные ответы, утечки в prompt, числа, неверные hash, падение инфраструктуры. Отдельно фиксировать изменение протокола и несовместимость результатов версий.
