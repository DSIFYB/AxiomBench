# Протокол v0.2 · итоговый балл equal-four-v1 (toolkit v0.2.1)

## Наборы и режимы

Starter v0.1: 32 исходных задачи. Extended v0.2: 900 публичных синтетических параметрических задач — 300 General, 300 Math, 150 C++ generation, 150 C++ repair. Они образуют 75 базовых семейств; C++ использует два режима, поэтому групп family/mode 90. У каждой группы 10 зависимых вариантов.

`--profile quick` (по умолчанию) выбирает по первому варианту на family/mode: 90 задач. `--profile full` выбирает все 900. Starter не имеет параметрических family и поэтому даёт все 32 в обоих профилях. Track фильтруется до выбора профиля. Quick подходит для первого запуска и проверки широкого покрытия семейств, его нельзя представлять как полный результат 900 задач.

Single-shot: один сохраняемый ответ на задание, без инструментов и evaluator feedback. C++ repair получает исходно ошибочную программу и возвращает полный исправленный файл; это не цикл повторных попыток по скрытым тестам. Self-repair/agent режим пока не реализован.

## Ответы и баллы

| Тип | Формат | Проверка |
|---|---|---|
| General/json | Один объект `{"answer":...}` | Точное совпадение JSON с сохранением типов и порядка массивов |
| Math/number | Один объект `{"answer":"p/q"}` или число | Равенство точных рациональных чисел; выражения не исполняются |
| C++ | Один fenced-блок cpp/c++ | Полная программа C++20 проходит все проверочные случаи |

General проверяет рассуждение и следование инструкции; полное академическое знание MMLU-Pro не покрывается. Математика проверяет итоговое число и не доказывает правильность вывода; доказательства и символические ответы требуют другого evaluator. Формат влияет на итоговую оценку; отдельно показывается invalid_format.

C++ получает 1 при прохождении всех случаев, иначе 0. Пробелы/переводы строк незначимы, stdout сравнивается по токенам. После первого проваленного случая дальнейшие тесты задачи пропускаются: решение уже не может получить 1. В отчёте есть executed_test_cases и total_test_cases. Тесты покрывают типовые границы, негативные случаи, случайные входы и некоторые большие массивы; заявленная асимптотика всех задач ещё не проверяется предельными стресс-тестами.

В отчёте четыре основные оценки: General, C++ generation, C++ repair, Math. Сохранены task-level статусы и категории. Общий «IQ» не вычисляется. Агрегаты включают family_count и среднее accuracy по семействам. При наличии зависимых вариантов IID Wilson interval подавляется; для единичных семейства/задач он остаётся только ориентиром с предположением независимости, а не доказательством репрезентативности.

Итоговый **AxiomBench Score (0–100)** в toolkit v0.2.1: `25 × (General_passed/General_total + Math_passed/Math_total + Generation_passed/Generation_total + Repair_passed/Repair_total)`. Протокол `equal-four-v1` использует task accuracy, а не family macro. Каждое направление имеет вес 25% независимо от числа задач. Среднее вычисляется из точных долей без предварительного округления процентов. HTML показывает целый балл с округлением половин вверх; `overall.score` в JSON и подпись в HTML сохраняют два знака после запятой.

Если какого-либо направления нет, `overall.score = null`, статус `unavailable`: веса не перераспределяются. Пропуски и API errors остаются в знаменателе, дают статус `provisional` и `comparable = false`. Завершённый прогон всех направлений даёт статус `complete`. Сравнивать следует одинаковые suite hash, профиль, выбранные задания, версию evaluator/формулы и настройки модели/компилятора. Больший балл — лучшее среднее на данном наборе; небольшая разница не является проверкой статистической значимости. Quick и Full нельзя объединять в один рейтинг. Старые отчёты без итогового балла можно повторно получить через grade из сохранённых ответов; задания и проверяющие критерии в v0.2.1 не менялись.

## Ошибки и инфраструктура

Все выбранные задачи входят в знаменатель, включая пропуски и API errors. API-сбой останавливает дальнейший сбор после записи ошибочного элемента. Неполная оценка возвращает код 2 и сохраняет report для диагностики. Обычный неверный ответ — измеренный результат, а не ошибка программы.

Повторные/неизвестные ID, несовпадающий suite/track/profile или недоступная контейнерная инфраструктура прерывают проверку с кодом 1. Это не превращается в ошибку модели. Metadata проверяется до исполнения кода. При ручном импорте без metadata условия получения ответов нельзя подтвердить автоматически.

## API и продолжение

CLI `run`: temperature=0, max_tokens=2048 по умолчанию. Launcher scripts/run_local.py: max_tokens=4096. Ожидание одного API-ответа — 180 секунд. Model server управляет своим контекстом, quantization и внутренним reasoning budget; они не уравниваются одним max_tokens. Для сравнений их нужно указать в дополнении к отчёту.

Сборщик использует отдельный новый user-message для каждого задания: история предыдущих задач модели не передаётся. Prompt содержит только условие и, для repair, buggy code; gold answer, скрытые tests, reference и verification_method туда не входят.

`--resume` допускается только для одинаковых suite hash, selected IDs, profile, track, model, endpoint, temperature и max_tokens. Уже сохранённые ответы не повторяются, включая записанные API errors. Повреждённая строка не удаляется автоматически. Незавершённый запрос мог исполниться без сохранения ответа и при resume может повториться; такой прерванный прогон не обеспечивает строго один фактический API-запрос на элемент. Для чистого сравнительного прогона выбери новый файл.

Ключ читается из AXIOMBENCH_API_KEY и не записывается. JSONL содержит response, latency, prompt hash, usage и finish_reason, если сервер их возвращает. metadata содержит настройки и время начала. Report содержит suite/answer hashes, версию evaluator, выбранный профиль и Docker image ID. Endpoint не должен содержать секреты в URL.

## C++ среда

Docker с Linux-контейнерами, immutable resolved image ID, GCC 14, `-std=c++20 -O2`. Одна компиляция на задачу в отдельный private named volume. У каждого теста новый runtime-container с бинарником в read-only volume; исходник и остальные тесты runtime не доступны. Названный volume и контейнеры удаляются после оценки, в том числе при таймауте.

Сеть отключена, capabilities сняты, root filesystem read-only. Runtime — UID/GID 65534. Один CPU, 512 MiB памяти без дополнительного swap, 64 процесса, CPU limit 10 секунд, tmpfs 64 MiB. Wall time compilation — 45 секунд, execution с запуском контейнера — 15 секунд на случай; captured output ограничен 1 MiB. Контейнерный запуск неизбежно зависит от Docker/OS overhead: этот development-протокол не является официальным competitive-programming лимитом.

## Что проверено при подготовке

- Starter: 8 доверенных C++ эталонов, 34 случая, 4 обнаруженных ошибки.
- Extended: 150 доверенных C++ эталонов, 3900 случаев; те же случаи предназначены для 150 paired repair-задач, всего 7800 case entries.
- Все 150 buggy variants проваливают хотя бы один случай.
- Все 300 Math ответов проверены отдельным standard-library verifier: переборы, отдельные формулы, интеграл через точное правило Симпсона, determinant через перестановки и др.
- Unit/integration тесты проверяют формат, hashes, выбор профилей, resume и API с mock server; это не реальные модельные результаты.

Эталоны и мутации проверялись доверенно на локальном GCC. Контейнерный evaluator имеет отдельный CI smoke job; его фактический статус нужно смотреть в GitHub Actions. Набор пока не прошёл независимую человеческую вычитку/калибровку и не гарантирует отсутствие похожих задач в обучении.

## Дальнейшая научная оценка

Фиксировать commit набора и evaluator, model revision, точные бюджеты, quantization/hardware и непрерывность прогона. Добавлять независимые задачи, предметные знания и разрешённые official snapshots. Private eval хранить отдельно от публичных ответов и не использовать для тренировки/prompts tuning. Не сравнивать наш subset/адаптированный протокол с официальными полными баллами.
